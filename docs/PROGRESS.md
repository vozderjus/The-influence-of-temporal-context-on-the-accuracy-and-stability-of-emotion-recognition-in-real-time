> Этот файл — «память» между сессиями. Обновлять в конце каждой сессии.

## Текущее состояние кратко
Код из ветки `emotion_recognition` (модуль `emotion_detection.py`) объединён со Streamlit-приложением
из архива `emotion_project1.zip` (Telegram). Приложение разложено по модулям,
распознавание идёт через единую функцию `get_emotions()`.
**Трекинга и временного сглаживания (главная тема исследования) пока нет.**

## Что сделано

### Сессия 2026-11-12 — объединение модуля и приложения из архива
Исходные материалы:
- ветка `emotion_recognition`: `emotion_detection.py` — `get_emotions(path)` на DeepFace,
  принимал только путь к файлу, удалял `surprise`;
- архив: `app.py` (1011 строк, всё в одном файле), `requirements.txt`, `instruction.html`;
- документ «Разбор_проекта_Emotion_Recognition.docx» — описание архитектуры приложения из архива.

Изменения:
1. **`emotion_detection.py`** расширен (обратно совместим по формату ответа):
   - вход: путь `str` **или** numpy BGR (кадр / вырезанное лицо);
   - `model="deepface" | "vit"` — ViT (`trpakov/vit-face-expression`) перенесён из приложения;
   - `is_face_crop=True` — лицо уже найдено BlazeFace, DeepFace не ищет его повторно
     (`detector_backend="skip"`);
   - метки обеих моделей приводятся к 6 классам `EMOTIONS`, `surprise` убирается,
     вероятности **перенормируются** до 100;
   - `load_vit_model()` кэшируется (`lru_cache`).
2. **`app.py`** из архива разбит на модули:
   - `face_detection.py` — BlazeFace, модель автоматически скачивается в `models/`;
   - `visualization.py` — цвета, русские названия, шрифты, `draw_overlay`;
   - `report.py` — график, выбор ключевых кадров, PDF;
   - `app.py` — только интерфейс; вместо `analyze_frame` вызывает `get_emotions`.
3. **Исправлены ошибки, найденные при объединении:**
   - старый модуль: после удаления `surprise` `dominant_emotion` мог остаться `surprise`,
     сумма вероятностей была меньше 100;
   - архив: в DeepFace подавались кадры в RGB, а DeepFace ждёт BGR;
   - архив: ViT-пайплайн по умолчанию возвращает только топ-5 классов из 7 — теперь `top_k=None`;
   - архив: два одинаковых словаря цветов (`EMOTION_COLORS` и `EMOTION_COLORS_RGB`) — оставлен один;
   - архив: модель `.tflite` искалась в текущей папке запуска — теперь путь берётся от расположения модуля.
4. Служебное: `requirements.txt`, расширенный `.gitignore` (`artifacts/`, `models/`, `venv/`, `__pycache__/`),
   инструкция → `docs/instruction.html` (обновлён список файлов), раздел «Запуск» в `README.md`,
   `CLAUDE.md` с соглашениями.
5. В видео-вкладке добавлен формат `.flv` (в нём лежат видео CREMA-D).

Проверка: см. раздел «Проверено / не проверено» ниже.

## Проверено / не проверено
Проверено 2026-11-12 (Windows, Python 3.11, `.venv`):
- все модули компилируются и импортируются;
- на кадрах CREMA-D (`1001_DFA_HAP_XX.flv`, `1001_DFA_ANG_XX.flv`, кадр 30):
  BlazeFace находит лицо; `get_emotions` для `deepface` и `vit` возвращает 6 классов, сумма = 100;
  HAP → оба `happy`; ANG → ViT `angry`, DeepFace `neutral` (одиночный кадр, не метрика);
  первый вызов ViT ~30 с (загрузка модели), дальше ~0.1 с на лицо;
- старый вызов по пути к файлу `get_emotions("file.png")` работает; на `None` — пустой ответ;
- PDF-отчёт собирается (`report.generate_pdf_report`);
- `streamlit run app.py` стартует, интерфейс открывается (шапка, выбор модели, 3 вкладки).

Не проверено:
- загрузка фото / видео через интерфейс в браузере и PDF из видеовкладки (логика та же, что в проверенных функциях);
- веб-камера (WebRTC) — нужен браузер с камерой.

Найдено при проверке: для `tensorflow>=2.16` DeepFace требует пакет **`tf-keras`** — без него DeepFace
молча возвращал пустой результат. Добавлен в `requirements.txt`.

## Что осталось сделать (по порядку)
1. **Трекинг лиц** — `tracking.py`: стабильный ID для каждого лица между кадрами
   (например, IoU-трекер или SORT). Сейчас лица сопоставляются просто по порядку площади —
   при нескольких лицах эмоции «перескакивают» между людьми.
2. **Временное сглаживание** — `smoothing.py`: история вероятностей на каждый ID трека;
   режимы: покадровый (без сглаживания), скользящее среднее (окно N), EMA (коэффициент α).
   Только причинное сглаживание (по прошлым кадрам). Встроить в видео и веб-камеру + переключатель в UI.
3. **Офлайн-эксперименты на CREMA-D** — скрипт без Streamlit (`experiments/run_eval.py`):
   - докачать видео: `git lfs pull --include "VideoFlash/*"` в `artifacts/CREMA-D-small`
     (сейчас скачано ~82 из 7442, остальное — LFS-заглушки);
   - метка эмоции берётся из имени файла (`1001_DFA_ANG_XX.flv` → `ANG` → `angry`);
   - метрики: Accuracy, Precision, Recall, Macro F1; число переключений класса,
     средняя длительность устойчивого предсказания; FPS и latency;
   - в CREMA-D одна эмоция на клип → для замера задержки реакции склеивать клипы с разными эмоциями.
4. Сравнение моделей (DeepFace vs ViT) и параметров сглаживания (размер окна, α) → таблицы и графики для статьи.
5. Опционально: убрать устаревшие аргументы fpdf2 (`ln=True`) — сейчас дают только предупреждения.

## Известные проблемы и ограничения
- Python 3.13+ не подходит (TensorFlow). На ПК пользователя `.venv` пересоздан на Python 3.11.
- Зависимости весят 3–5 ГБ (TensorFlow + PyTorch).
- Модели обучены на FER2013 (фронтальные лица) — на повёрнутых лицах точность падает.
