# Офлайн-оценка: `experiments/run_eval.py`

Скрипт считает метрики исследования на видео-датасетах RAVDESS и CREMA-D
для моделей DeepFace / ViT и режимов временного сглаживания.

## Файлы
| Файл | Что делает |
|---|---|
| `run_eval.py` | Точка входа: выбор клипов → покадровые предсказания (с кэшем) → сглаживание → метрики → CSV |
| `clip_datasets.py` | Список клипов и меток из имён файлов RAVDESS / CREMA-D |
| `eval_metrics.py` | Accuracy, Precision, Recall, Macro F1, матрица ошибок, переключения, задержка реакции |
| `local_paths.example.json` | Образец файла с путями к датасетам |
| `../smoothing.py` | Сглаживатели `none`, `ma:N`, `ema:A` (онлайн, причинные) — общие с будущим приложением |

## Подготовка (один раз на компьютере)
Скопировать `local_paths.example.json` → `local_paths.json` и вписать свои пути
(файл в git не попадает). Тогда `--root` можно не указывать.
```json
{
  "ravdess": "E:/Education/.../ravdess_work/extracted",
  "cremad": "artifacts/CREMA-D-small"
}
```
CREMA-D: видео в Git LFS, по умолчанию скачано ~82 из 7442 (остальные — заглушки,
скрипт их пропускает). Докачать: `git lfs pull --include "VideoFlash/*"` в папке датасета.

## Запуск
Из корня проекта, с активированным `.venv`:
```
python experiments/run_eval.py --dataset ravdess --actors 01 02 --intensity strong --stride 3 --models deepface vit --transitions 30 --out results/pilot_ravdess
```

| Параметр | Значение |
|---|---|
| `--dataset` | `ravdess` или `cremad` |
| `--root` | папка датасета (иначе из `local_paths.json`) |
| `--actors` | номера актёров (`01 02 …`), по умолчанию все |
| `--emotions` | только эти эмоции (`angry disgust fear happy sad neutral`) |
| `--intensity` | `all` / `normal` / `strong` (neutral в RAVDESS только normal — сохраняется всегда) |
| `--per-label N` | не более N случайных клипов на эмоцию (сбалансированная выборка) |
| `--limit N` | не более N клипов всего |
| `--models` | `deepface`, `vit` или оба |
| `--modes` | режимы сглаживания, по умолчанию `none ma:5 ma:15 ema:0.3 ema:0.1` |
| `--stride N` | анализировать каждый N-й кадр (3 → 10 кадров/с при 30 FPS) |
| `--transitions N` | число склеенных пар клипов для замера задержки реакции |
| `--stable-frames K` | сколько проанализированных кадров подряд новая эмоция должна держаться (по умолч. 5) |
| `--seed` | зерно для `--per-label` и выбора пар |
| `--force` | пересчитать кэш предсказаний |
| `--out` | папка результатов (по умолчанию `results/<дата-время>`) |

**Время (CPU этого ПК, `--stride 3`):** DeepFace ≈ 0.8 с на клип, ViT ≈ 5 с на клип.
Весь RAVDESS (968 уникальных клипов): DeepFace ≈ 13 мин, ViT ≈ 80 мин.
Прерывать можно (Ctrl+C): готовые клипы уже в кэше, повторный запуск продолжит.

## Как устроено
1. **Клипы.** Метка — из имени файла. RAVDESS: calm и surprised пропускаются;
   модальности 01 и 02 — одинаковое видео, берётся одна (01). CREMA-D: заглушки LFS пропускаются.
2. **Покадровые предсказания** (дорого, кэш `results/cache/<датасет>/<модель>_s<stride>/<клип>.npz`):
   на каждом N-м кадре BlazeFace ищет лица, самое крупное вырезается и идёт в
   `get_emotions(..., is_face_crop=True)`. Сохраняются вероятности 6 классов, время детекции и распознавания.
3. **Сглаживание** (дёшево): вероятности кадр за кадром подаются в сглаживатель, прогноз = argmax.
   Кадры без лица пропускаются — состояние сглаживателя не меняется.
   Так как сглаживание причинное, результат совпадает с обработкой видеопотока в реальном времени.
4. **Задержка реакции.** В клипах одна эмоция, поэтому смена эмоции моделируется склейкой:
   берутся пары клипов **одного актёра** с разными эмоциями, их покадровые вероятности
   ставятся подряд (A → B), сглаживатель идёт по всей цепочке без сброса.
   Задержка = время от первого кадра B до момента, с которого новая эмоция держится `K` кадров подряд.

## Выходные файлы (`--out`)
| Файл | Содержимое |
|---|---|
| `summary.csv` | одна строка на (модель, режим) — все метрики ниже |
| `per_clip.csv` | одна строка на (модель, режим, клип): доля верных кадров, прогноз большинством, переключения |
| `confusion_<модель>_<режим>.csv` | матрица ошибок по кадрам (строки — истина, столбцы — прогноз) |
| `config.json` | параметры запуска, число клипов, список пар для задержки |

### Метрики `summary.csv`
| Колонка | Смысл | Исследовательский вопрос |
|---|---|---|
| `accuracy`, `precision_macro`, `recall_macro`, `f1_macro` | по кадрам с найденным лицом; истина = метка клипа | 2 |
| `f1_<эмоция>` | F1 по каждому классу | 2 |
| `clip_acc_majority` | доля клипов, где самый частый прогноз = метке | 2 |
| `switches_per_clip`, `switches_per_sec` | сколько раз меняется прогнозируемый класс | 1, 3 |
| `mean_stable_sec` | средняя длительность отрезка с одним прогнозом | 3 |
| `delay_sec_mean`, `delay_sec_median` | задержка реакции на смену эмоции (только успешные пары) | 4 |
| `delay_miss_rate` | доля пар, где новая эмоция так и не установилась до конца клипа B | 4 |
| `face_rate` | доля кадров, где найдено лицо | — |
| `det_ms`, `emo_ms` | среднее время детекции и распознавания на кадр, мс | 6 |
| `smooth_us` | время сглаживания на кадр, мкс | 6 |
| `fps_pipeline` | 1000 / (det_ms + emo_ms) — сколько кадров/с успевает конвейер | 6 |

## Ограничения
- Вопрос 5 (трекинг, несколько лиц) этим скриптом не покрывается: в RAVDESS и CREMA-D одно лицо в кадре.
- Метка клипа приписывается всем его кадрам, хотя в начале и конце клипа лицо часто нейтральное —
  это занижает accuracy для всех режимов одинаково.
- `delay_sec_mean` считается только по успешным парам — смотреть вместе с `delay_miss_rate`.
- Модели обучены на FER2013, не на RAVDESS/CREMA-D.
